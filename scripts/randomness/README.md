# scripts/randomness · 随机性审计（双色球深检 + 8 彩种扩展）

问题很具体：**开奖里有没有可利用的统计结构？** 这套脚本每月把它跑一遍并自动出报告。
零依赖（只用 node 内置模块，仓库里没有 node_modules，也必须保持没有）。

```bash
node scripts/randomness/fetch-ssq.mjs    # 拉双色球全量历史 + 与官方接口交叉校验 → data/ssq.json
node scripts/randomness/analyze.mjs      # A/B/C/D/E 全套检验 → stdout + docs/randomness-latest.md
node scripts/randomness/fetch-multi.mjs  # 拉其余 7 彩种全量历史 + 结构校验 + 与线上 D1 交叉校验 → data/{kind}.json
node scripts/randomness/analyze.mjs --all       # 双色球深检之后，再跑 8 彩种扩展审计 → docs/randomness-multi-latest.md
node --test scripts/randomness/stats.test.mjs   # 统计内核单元测试
```

可选：`node scripts/randomness/analyze.mjs 6000`（改模拟次数）；环境变量
`RANDOMNESS_ALLOW_STALE=1`（离线复现历史结论时跳过新鲜度闸门）、`RANDOMNESS_USE_CACHE=1`
（fetch 复用本地 `data/ssq_asc.txt`）。`.github/workflows/randomness.yml` 每月 1 日跑一次，
不需要任何 secrets，并把生成的 markdown 存成 artifact。

数据源：`http://data.17500.cn/{ssq,dlt,3d,pl3,pl5,7lc,7xc,kl8}_asc.txt`（各自 2002~2026 年全量）。
双色球额外配 `cwl.gov.cn` 官方接口做逐字段交叉校验；其余彩种的公共 API 内部也读 17500，
**与备源同源**，所以那几项验的是「列映射解析是否正确（独立实现）」而不是「数据源是否独立」——
报告里逐条标注了这一点，不冒充双源。

**覆盖范围界定（别把两套结论互相套用）**：

- 开奖侧（均匀性 / 独立性 / 稳定性 + 族内联合校正 + 检测功效）：8 个彩种全做。
- 投注侧 + 经济学（按销量归一的拥挤度、安慰剂、返奖率）：**只有双色球做了全套**，
  因为只有它的各奖级注数列经过官方接口逐字段校验。其余彩种的奖级/销量列未纳入经济性结论。

## 五个板块

| 板块 | 问的问题 | 关键读数 |
|---|---|---|
| 0 验收 | 这次跑挂了吗 | 观测值逐位复现、ω=1 精确超几何、零分布期望 = 27、开奖日只落在二/四/日 |
| A 均匀性 | 每个号被开出的机会一样吗 | 红球 χ²(33格)、蓝球 χ²(16格)、逐号 z 表、冷热极值、**族内联合校正** |
| B 独立性 | 这期和上期有关系吗 | 与上期重合数、蓝球重复率、lag-1 自相关、遗漏均值/最大、**开奖顺序位置 χ²**、和值/跨度/奇偶/连号/同尾/三区 |
| C 稳定性 | 有偏会留下可复现的痕迹吗 | split-half 热号相关、Top6 重合置换检验、分年代（各年代自己的零分布）、分开奖日 |
| D 投注侧 | 别人怎么选号 | 生日区(≤31)、蓝球冷热、尾数 8/4、连号；全部按**每亿元销量**归一化，每条效应配一个**安慰剂** |
| E 经济学 | 这一切值多少钱 | 返奖率、冷号策略的增量（百分点）、要检出 5% 球偏需要多少期 |

## 六条铁律（违反任何一条，这套东西就开始说谎）

1. **逐号频次的零分布不是 df=32 的卡方。** 一期开出的 6 个红球互不相同 ⇒ 33 个格子负相关 ⇒
   `E[χ²] = 33 × (1 − 6/33) = 27`。用解析 df=32 会把真实的 `p=0.021` 粉饰成 `p=0.069`。
   本套件一律用蒙特卡洛构造零分布；解析值只打印出来当反面教材。跑起来后第 0 节会**断言**
   模拟出来的 χ² 均值 ≈27（而不是 32），断言不通过就直接 exit 1。
2. **真实数据和模拟数据必须共用同一个统计函数，并且模拟要保持“不放回”。** 任何“两份实现”的分叉
   都会造出假的显著。模拟里 `red` 数组要为跨度/连号**排序**，但位置检验必须另存**原始开奖顺序**
   `ord` ——早期草稿把两者混为一谈，立刻冒出一个假的“第 3 位显著”。
3. **投注侧靠安慰剂识别，不是靠 p 值大小。** 一等奖=6红+1蓝、二等奖=6红**无**蓝、六等奖=**只看**蓝。
   所以红球特征必须在含红奖级有效、在纯蓝的六等奖上为 NULL；蓝球特征必须在含蓝奖级有效、在纯红的
   二等奖上为 NULL。**任一安慰剂显著 = 实现里有混淆 = 整套结论作废**：analyze 以 exit 1 结束，
   报告里留下 `PLACEBO: FAIL`，工作流另有显式断言步骤把构建打成红。
4. **中奖注数必须按销量归一化（每亿元），并且要换年代、换开奖日复现。** 不然“效应”可能只是销量波动的影子。
5. **不许报挑出来的最小 p。** 诚实的读数是把相关的均匀性族标准化后取 `max|z|`，再用同一次模拟的联合零分布
   算校正后 p（A2 节）。33 个号 × 6 个年代 = 198 个格子，任何“冷热号定位”都是事后挑选。
6. **必须确定性、必须自证。** 固定种子（`SEED=20260909`），报告先打印验收检查（观测值逐位复现、
   ω=1 的精确超几何核对），让后来的人能区分“跑挂了”和“真的是零结果”。
   逐位复现的那组金标准只在**钉住的历史窗口**（`code ≤ 2026104` 的 3501 期）上比对——
   全量数据每月变长，若拿整份文件比，下一次开奖就会让验收失败，把“统计函数写坏了”和“数据更新了”混成一谈。
   数据缺失或最新一期超过 45 天，analyze **拒绝运行**（exit 2）而不是给一个好看的空结论。

## 文件

- `lib.mjs` — 统计内核（χ²/正态/Mann-Whitney/Pearson/Spearman、mulberry32 + 部分 Fisher-Yates、
  超几何与非中心超几何、Sakamoto 星期、共用的 `statsOf`、蒙特卡洛与新鲜度闸门）。血泪教训写在文件头。
- `fetch-ssq.mjs` — 下载 → 结构校验 → 与 `cwl.gov.cn` 官方接口逐字段交叉校验（先 GET 公示页拿 cookie，
  再带 UA + Referer 打 `findDrawNotice`，否则 result 为空）→ 写 `data/ssq.json` 与原始 txt。
  网络不可用时打印原始错误并以非零码退出，**不写半成品、不静默成功**。
- `analyze.mjs` — 五个板块 + 报告落盘 + 退出码。`--all` 再挂上多彩种扩展；多彩种没跑全时**非零退出**，
  否则「8 彩种没问题」和「8 彩种没跑成」在 CI 里长得一模一样。
- `lib-kinds.mjs` — 彩种参数表（池大小 / 每期开出数 / pool vs digit 型）+ 通用组统计与模拟。
  零分布期望一律 `pool × (1 − k/pool)` 现算，**绝不硬编码 33/6/27**（那是双色球的数）。
- `fetch-multi.mjs` — 7 个彩种的下载 + 结构校验（值域 / 重复 / 跳号）+ 与线上 `D1` 公共接口逐期号码交叉校验。
- `multi.mjs` — 8 彩种开奖侧引擎（A/B/C + Bonferroni 联合校正 + 检测功效），写 `docs/randomness-multi-latest.md`。
- `stats.test.mjs` — 内核单元测试，期望值取自教科书/手算（不是从实现里抄的）。
- `data/*.json` — 已提交的全量历史基线（离线也能复现本仓库文档里的结论）。
  `data/*_asc.txt` 是 fetch 顺手留下的原始档，不进仓库。

## 结论长什么样

看 `docs/randomness-2026-09.md`（双色球首个基线）、`docs/randomness-latest.md`（双色球本月自动产物）、
`docs/randomness-multi-latest.md`（8 彩种扩展）。
一句话版：**8 个彩种的开奖序列都与「独立均匀（池内不放回）」齐平，开奖侧没有可利用结构；
唯一真实、可测量、可复现的结构是其他玩家的选号偏好，它只影响你中奖之后能留下多少，不改变中奖概率。**

随机游戏，统计仅供娱乐，不保证中奖。
